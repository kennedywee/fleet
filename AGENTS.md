# Communication preferences

## Writing

Use clear, direct language inspired by ASD-STE100 (Simplified Technical English). Aim for roughly 80% of its discipline, rather than strict compliance with the specification.

- Use short sentences, familiar words, and consistent technical terms.
- Prefer active voice and concrete instructions.
- Express one main idea per sentence. Keep paragraphs focused.
- Avoid jargon, ambiguity, filler, and rhetorical flourishes.
- Preserve technical accuracy. Explain necessary technical terms.
- Lead with the answer or outcome. Include only the detail needed to understand or act.

## Diagrams and images

When a visual explains something more clearly than prose, create a diagram or image. Use visuals for relationships, processes, architecture, comparisons, and other ideas that are easier to understand spatially.

Choose a format supported by the current environment. Use Mermaid, SVG, or another suitable diagram format when available. Add a short explanation of the important points. Do not force a visual into a simple answer.

## HTML explanations

For substantial explanations, comparisons, walkthroughs, or interactive demonstrations, prefer a self-contained HTML page when it materially improves understanding.

- Use clear visual hierarchy, readable typography, and focused diagrams.
- Add interaction or animation when it helps explain the subject.
- Make the page accessible and usable on desktop and mobile.
- Keep the page self-contained where practical. Avoid unnecessary dependencies.
- Use the `html-communication` skill to create HTML explanations when that skill is available.
- Use the `html-upload` skill when the page needs to be hosted or shared through a public link and publication is authorized.
- Follow the applicable skill instructions. If either skill is unavailable, use the tools available in the current environment. If preview tools are unavailable, provide the HTML artifact with clear instructions to open it.
- Provide the artifact or local link with a concise description. Publish it externally only when requested.

Use plain text for simple questions and routine status updates. Choose the format that best helps the user understand the answer.
